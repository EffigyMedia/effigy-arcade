### RLG-228 — The ambulance is a generic blob in the rearview mirror

**REPORTED 2026-09-12, from the device.** Owner: *"the ambulance is showing as a generic blob in the
rearview mirror."*

**DIAGNOSED, NOT BUILT.** The mechanism is found and named below; no code has been changed.

---

## THE MECHANISM

The mirror shows the vehicle behind you, so it needs that vehicle's **face**. `drawMirrorFull` picks
one three ways: a police car by which of the two it is, a racer by body and paint through
`racerFront`, and **a traffic vehicle by its `type`, out of the `FRONT_SP` cache**.

`FRONT_SP` is built from a hand-written list of traffic kinds:

    for(const kind of ['sedan','sedan2','hatch','coupe','tuner','muscle','pickup','van'])

plus `taxi`, `cop` and `truck` built individually further down, and the supercars on their own terms.

**`ambulance` is in none of them.** A traffic ambulance carries `type: 'ambulance'`, so
`FRONT_SP[it.o.type]` is undefined; it has no `body`, so the racer branch is skipped; `fs` comes out
null and the mirror falls through to the **defensive grey lozenge** — which the code's own comment
describes as the block kept for *"a vehicle with no front sprite at all"*, adding *"Nothing in the
fleet is in that state any more."* Something is. That block is the blob the owner saw.

The REAR is fine, which is why this was never noticed from the road: `SP.ambulance` is built and the
vehicle looks right from behind. A face is only ever wanted when the vehicle is coming at you.

**This is the same omission as [[RLG-225]] and [[RLG-226]]** — a list of vehicles written before the
ambulance existed and never revisited. Third instance in one day.

## THE GUARD HAS THE SAME HOLE, AND THAT IS THE WORSE HALF

`tools/face-test.py` exists for precisely this defect. Its own header says three vehicles have
already been found with no face in the mirror — the racers, the police, and every car before the
front painters existed — and that *"each one was found by eye, on a phone, weeks after it
shipped."* It asks `API.frontOf` the same question `drawMirrorFull` asks, for every vehicle at once.

Its vehicle list is hand-written:

    const TRAFFIC = ['sedan','sedan2','coupe','tuner','muscle','pickup','van','taxi','truck'];

**Neither `ambulance` nor `hatch` is in it.** So the check that would have caught this on the day the
ambulance landed passed green, because it never asked about the ambulance. `API.frontOf` answers
correctly and nobody put the question.

This is the strongest argument on the record for [[RLG-227]]: the defect is not that a list was
wrong, it is that **a list of vehicles is written by hand at all** — including inside the tool
written to stop it.

## WHAT A FIX LOOKS LIKE

1. **Build `FRONT_SP.ambulance`.** The rear already uses `paintRig('ambulance', ...)`, which remaps
   the kind to `van` and adds the `medical` bar; `paintRigFront` has the matching remap, and its
   comment at the front painter says the bar is *gated off* the ambulance there. **Read that gate
   before building — the face may be deliberately barless, and if so this needs the owner's eye on
   what an ambulance's front looks like rather than a copy of the van's.**
2. **Make `face-test.py` stop carrying a list.** It should enumerate the vehicles from the engine,
   the way `knob-test.py` does through `API.fleet()`. A guard that names its own subjects can only
   ever check the ones somebody remembered.
3. **Falsify it.** Serve the build with `FRONT_SP.ambulance` removed and watch the check fail. A
   check that has never failed on this vehicle has proved nothing about it.

## WHAT IS NOT KNOWN

Whether any OTHER traffic kind is in the same state. `hatch` is in the `FRONT_SP` build loop but not
in the harness list, so it is covered in the game and unchecked by the guard — the reverse case.
**Nothing has enumerated the two lists against each other.** That comparison is the first step of
the fix and it has not been run.
