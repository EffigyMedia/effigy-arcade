### RLG-147 — Returning from pause during a run gets a new countdown
- **RULED 2026-09-01T16:54:36-04:00** — Owner, 2026-09-01, mid-session: "Whenever you pause the game and you return during a run, we
need a new countdown."

A PAUSE HANDS THE CAR BACK AT SPEED AND SAYS NOTHING. The shell's pause stops the loop and the
resume starts it again in the same frame the player left, so a car doing 180mph is under the
player's thumb before the eye has found it. The count-in exists for precisely that moment at
the start of a run - `countIn` gates the throttle and the launch for three seconds and the
picture says how long is left - and the same argument applies on the way back from a pause.

IT MUST BE THE SAME COUNT-IN, NOT A SECOND ONE. `countIn`, `countFrom` and `countPip` are the
mechanism, `step()` runs them down, `drawCount` and `drawGo` paint them, and the launch meter
reads `countIn > 0` to know it is armed. A resume that drew its own three-two-one would be a
second answer to one question and the two would drift apart the first time either is tuned.
Setting `countFrom = countIn = <n>` on resume is the whole of it, and everything that already
watches that variable follows for free.

TWO THINGS TO SETTLE WITH THE OWNER BEFORE BUILDING.

    HOW LONG. The start line is 3.0 seconds. A resume may want less - the player already knows
    the road - and one number is cheap to change but not cheap to guess at.

    AND WHETHER THE CAR IS HELD. At the start the car is stationary and the count holds the
    throttle. Mid-run it is not: holding the throttle for three seconds at 180mph is a coast
    down a straight, which is a penalty for pausing, and freezing the world instead is a
    different feel again. The likely answer is that the world stays frozen until the count
    reaches zero, which is what a console game does - but it is the owner's call because it
    decides whether pausing is free.

AND IT IS BOTH DRIVING GAMES. `countIn` is in `road.js`, so Interstate and Motorsport get this
together unless it is gated - and there is no reason to gate it. Whether Quietus and Hardpoint
want the same thing is a separate question that this ruling does not answer.
- **RULED 2026-09-19T08:47:28-04:00** — DECIDED, owner, 2026-09-19: the world stays FROZEN until the count reaches GO, then the car carries on at the speed it paused at - pausing costs nothing. The count is 3 seconds, the same as the start line.
- **RULED 2026-09-19T08:53:37-04:00** — BUILT, v0.14.82. Resuming from a pause mid-run starts a three-second count (`RESUME_COUNT`) with the WHOLE world frozen - road, traffic, rivals, clock, sky and sea - and the car carries on at the speed it paused at when GO shows.

IT IS THE START LINE'S OWN COUNT: the resume sets `countIn` and `countPip`, so the numbers, the pips and GO are the ones the start line uses. What differs is `resumeHold`, which returns from `step()` before anything moves; the start count holds only the player, because RLG-121 found a frozen world lurching at GO reads as a pop. A resume does not have that problem: the pause had already frozen the picture.

THE SHELL NOW SAYS WHEN IT HANDS A GAME BACK. It pauses by holding the game's animation frame, so a game cannot see the moment it is resumed, and a long frame is not a signal - a browser stall looks the same. `Arcade.onResume(fn)` is a generic hook in `arcade.js`, knowing nothing about any game. A new run clears any resume in progress.

PROVEN by `tools/resume-test.py`, through the real pause button and the pause menu's RESUME: a count of about three seconds starts; for 1.5 seconds the car's position and speed do not change; after GO it moves again at 7,488 against the 7,520 it paused at. The control - pausing on the title screen - starts no count. With the hook unregistered, four checks failed. launch-test and smoke-test pass.
