### RLG-039 — The other four harnesses cannot run as step evidence
- **RULED 2026-08-28T17:11:07-04:00** — **Tracked, not started.** Found while recording [[RLG-029]]: `step.py` cannot launch any harness
except `band-test.py`, so no other harness run can become step evidence.

`step.py` runs its command with the ENVIRONMENT root as the working directory. On Windows,
`CreateProcess` resolves a relative EXECUTABLE against the calling process's directory rather than
against the `cwd` it is handed, so `.venv/Scripts/python.exe` is unreachable by any relative path
from there. An absolute path would work and would put a drive letter into the evidence fragment,
which `Path_Policy.md` forbids. Three failed invocations are recorded as [[EVD-001]], [[EVD-002]]
and [[EVD-003]]; they are kept because they are the trail.

`band-test.py` works around it on its own: it is started by whatever Python is on PATH, and if that
one has no Playwright it hands over to the project `.venv` and exits with the child's code. The
same treatment is wanted for `drive-test.py`, `smoke-test.py`, `circuit-test.py`, `traffic-test.py`
and the rest, and it belongs in `harness.py` rather than being copied five times - with the
constraint that it must run BEFORE the `playwright` import, which is what makes it awkward to put
in a module those files import.

**This is the second time this exact Windows behaviour has cost something.** `harness.py` already
documents it for `node`, where a bare `"node"` missed `node.cmd` and failed with a message that
named neither node nor PATH. Worth stating once, in one place, rather than a third time.

Until it is done, a harness run is verified by a person reading the output rather than by an
evidence fragment, and the record should say so plainly instead of implying the run was attested.
- **RULED 2026-08-30T10:48:59-04:00** — SEVEN HARNESSES COULD NOT RUN AS EVIDENCE, AND THE REASON IS ONE LINE EACH. They served the folder
from `.` and imported from `tools`, which works from the project directory and nowhere else.
`step.py` runs a command with the ENVIRONMENT's root as its working directory - so `audio-test`
404'd on the cabinet it loads, `lamp-test` went looking for `P:/Code_Continuum/tools/drive-test.py`,
and both recorded a FALSE FAILURE in the permanent record while passing perfectly well by hand.

IT WAS FIXED BECAUSE IT BIT TWICE IN ONE SESSION. RLG-078's unit could not record the audio check and
RLG-077's could not record the lamp check, in the same morning. A harness that cannot be run as
evidence is a harness whose result is a claim rather than a record, which is the distinction this
whole store exists for.

The root is the file's own parent - `Path(__file__).resolve().parent.parent` - which the newer
harnesses already do and these seven predate. All seven now run from the environment root, and all
seven are recorded through `step.py` in this unit.

AND TWO THINGS FELL OUT OF ACTUALLY RUNNING THEM, both of which had been invisible while nobody
could.

one tap away). `menu-test.py` asserts its ABSENCE. So one harness was waiting for the exact thing
another one forbids. It uses OPTIONS now.

raised `IndexError` before it opened a browser.
