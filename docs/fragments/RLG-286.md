### RLG-286 — Fuel leaves Interstate and stays in the code for Motorsport
- **RULED 2026-09-16T23:56:58-04:00** — TRACKED, NOT STARTED. Owner, 2026-09-16: "As much as I like the fuel gauge. Let's take it out of interstate - but we will need it for Motorsport so keep it in code. Let's do the same for the Gerry can."

IT IS A CFG SEAM, NOT A DELETION, AND THE OWNER SAID SO IN THE SAME BREATH. "Keep it in code" is the whole instruction: `road.js` serves both driving games and must not know which one is running except through `CFG` (CLAUDE.md, architecture). So this is a switch Interstate sets and Motorsport does not, and every line of the fuel model stays exactly where it is.

THREE THINGS GO BEHIND THE SAME SWITCH, and they have to go together or the game contradicts itself: the fuel GAUGE in the HUD, the fuel BURN that drives it, and the JERRY CAN pickup that refills it. A can on the road that refills a tank nothing reads is a pickup that does nothing; a gauge with no burn is a dial that never moves - the decoration this project's own rule forbids ([[RLG-081]]: a dial that is not fed by anything).

WHAT TO CHECK WHEN IT IS BUILT. `drive-test.py` asserts fuel today and covers BOTH games, so it has to ask each game for what that game has rather than assert fuel unconditionally - the same shape `circuit-test` already uses for what a circuit must NOT have. And the jerry can is one of the pickups RLG-266 lays, so the count it lays changes with this.

AND IT IS A TUNABLE WITH A COMMITTED DEFAULT, not an edited-in-place constant.
