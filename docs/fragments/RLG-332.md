### RLG-332 — The biome sequence ping-ponged between two places
- **RULED 2026-09-23T20:47:56-04:00** — OWNER, 2026-09-23, from the device: "for some reason, I kept getting mountain to city to mountain to city to mountain to city to mountain to city. We also need to make sure that we don't ever roll the same biome back to back."

TWO THINGS, AND THEY ARE NOT THE SAME THING. The fault reported is an A-B-A-B PING-PONG: two places alternating for a whole run, which reads as a loop rather than a journey. The rule asked for is NO IMMEDIATE REPEAT: the same place must never follow itself.

A PICKER THAT ONLY REFUSES A-A CAN STILL PRODUCE A-B-A-B FOREVER, which is likely exactly what is happening - so satisfying the rule does not fix the report, and both have to be answered.

NOT STARTED. The first job is to read what picks the next place and whether it has any memory beyond the current one.
- **RULED 2026-09-23T21:00:20-04:00** — BUILT 2026-09-23.

MEASURED FIRST, AND THE REPORT REPRODUCED EXACTLY. `tools/place-walk-test.py` asks the picker for 300 crossings from several starts, which reads a fault that takes a dozen miles of road to show. From a cold MOUNTAIN, as it shipped:

  CITY MOUNTAIN TUNDRA MOUNTAIN TUNDRA CITY MOUNTAIN TUNDRA CITY TUNDRA CITY TUNDRA

118 returns-within-two in 300 crossings and 8 distinct places. From a cold CITY, 82. Even a warm FOREST start returned within two 54 times - about one crossing in six.

THE OWNER'S STATED RULE WAS ALREADY KEPT. No place has ever followed itself: `pickNext` refused `k === fromKey` before this change and the check reads 0 repeats on the shipped engine. THE FAULT REPORTED IS A DIFFERENT RULE - a picker with a memory of ONE can alternate between two places forever without once breaking it.

AND THE CLIMATE IS WHY IT SETTLES INTO A PAIR. A place may only be entered inside its own temperature range, and a run moves about 0.077 of the scale a crossing - ten degrees of a hundred and thirty. MOUNTAIN reaches 0.00 to 0.30 and CITY reaches 0.00 to 0.90; TUNDRA's window is 0.01 to 0.09 and every other place starts at 0.30. A run that settles cold has two places it can comfortably reach, so refusing only the current one leaves nowhere to go but back.

THE FIX IS A MEMORY OF THE PLACE BEFORE, and three passes in priority order. The first is the rule as stated. THE SECOND KEEPS THE PLACE RULE AND LETS THE WEATHER TAKE A DOUBLE STEP, because a cornered road should jump the climate rather than repeat itself - fifteen degrees is a thing nobody counts and a repeated place is a thing everybody does. Only the third gives the place rule up, and it exists so the generator can never return nothing and stop the game.

AFTER: 0 repeats and 0 returns-within-two across 1,500 crossings, twice over, from cold and warm starts alike, with 10 to 12 distinct places a walk. WATCHED FAILING at 66 returns with the memory taken back out.

A MIDDLE VERSION IS RECORDED BECAUSE IT LOOKED LIKE A FIX AND WAS NOT. With the memory but WITHOUT the double-step pass, one sample came back as a perfect three-place cycle - TUNDRA MOUNTAIN CITY TUNDRA MOUNTAIN CITY for all 300 crossings. It satisfies both of the owner's rules and would read exactly as wrong to a player. It is what sent this back for the second pass.

climate-falsify ABORTS, saying "rollWeather is not in the shape this proof knows how to break. The proof is stale, not the engine." IT ABORTS IDENTICALLY ON THE COMMITTED ENGINE - checked by putting HEAD's road.js back - so it is not this change, and it is a stale proof somebody should read. biome-test and novelty-test green, smoke-test 7/7.
