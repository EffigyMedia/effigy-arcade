### QUE-001 — the project clear tally

**7** context clear(s) counted in this scope, against **0** compaction(s), plus **6** session reset(s).

**The cadence counts 7 + 6 = 13.** A clear and a new session both turn the window over completely, so both pace maintenance ([[AUD-017]]). **The scoreboard below deliberately does NOT count resets** — it answers a different question.

**> That second number is the scoreboard for this release's central claim.** [[RLG-098]]: *the runtime is always heading for a compaction, and our clear only wins if it fires first.* Here the score is **nothing has compacted here yet** - the clear is winning outright. Before [[AUD-013]] the claim had no instrument.

This is **state, not config** — *every 3 clears* is a tunable and lives in `config.toml`; *we are 2 clears in* is this number ([[RLG-147]], §4 Q10).
It **travels with the drive**, because a tally that resets on a machine change never reaches its count.

*Holds the tally and nothing else. The queued tasks are `UNT-` fragments with status `queued` — a queue that also recorded work would be a tracker.*
