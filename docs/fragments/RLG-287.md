### RLG-287 — The audit gate applies to version releases, not to pushes for device testing
- **RULED 2026-09-18T20:54:53-04:00** — Owner, 2026-09-18, on the new audit rule: "That feels like an overreach of that policy." Asked which pushes the gate should apply to, the owner chose version releases only.

THE CLASH. MOD-003 added to the standing policy: "Before a release it is a gate: run audit-gate.py, and do not release until it prints GATE CLEAR." This project already rules that "A TESTABLE BUILD IS A RELEASE" (RLG-066), and it rules that for the opposite purpose - to make pushes FREQUENT, after 46 commits sat local while the phone tested a build fifteen versions old. Read together literally, every push for device testing would wait on a four-reader audit round, which undoes RLG-066.

THE RULING. For the audit gate, a release is a VERSION release: a minor version bump, a tag, or a game leaving the arcade as a standalone or a Godot conversion. A push to GitHub Pages so the owner can test a build on the device is not gated, and goes out as RLG-066 says. RLG-066 is unchanged for every other purpose.

The policy text is generated by the environment and a project may not edit it, so this ruling records the owner's reading for this project, and the environment line has been told so it can clarify the wording.
