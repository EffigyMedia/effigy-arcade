### RLG-244 — gate-test walks the gate by thumb, and the checks other harnesses own are gone from it
- **RULED 2026-09-14T08:45:04-04:00** — **What was wrong.** `tools/gate-test.py` failed six checks, and it failed the same six with the RLG-236 fix stashed (EVD-739). So the harness was at fault, not the build. Each failure was diagnosed before any change, and none of them is a game defect.

| Check | Cause |
|---|---|
| no car reaches a gear it does not have, and none loses one | The walk called `API.shift(dx, dy)`. RLG-203 later added the police shift's `API.shift()` further down `road.js`, and that assignment overwrites the gearbox wrapper. The walk moved nothing, so every car "reached" only gear 2, the gear it was sitting in. |
| a five-speed has fifth at the top of the third rail and neutral below it | The same dead walk. The expectation is also wrong by ruling: RLG-236 removed the slot below fifth. |
| a five-speed knob will not go below fifth at all | The same dead walk. `y ?` means the walk returned no rail-2 reading. |
| a six-speed goes down the same rail into sixth | The same dead walk. |
| the production and utility cars have the black knob, and only they | The list in the harness named six cars. `WORK_BODIES` has eight since HATCH and AMBULANCE were added. |
| a four-speed knob never leaves the two rails it has | The same dead walk. |

**The walk tested the wrong path as well.** `API.shift` wraps `shiftStep`, and the thumb does not go through `shiftStep` (RLG-220). So even an unshadowed wrapper tested the keyboard path, which is out of scope, and not the drag listener that ships.

**The repair.** The walk now holds a real pointer (`page.mouse`) on the knob. It finds the cross rail by scanning down on the first rail, sweeps the cross rail from far left to far right, and pulls hard up and hard down on every rail it finds. It reads `API.gate()` after each move. It computes no rail position of its own. Two checks replace the walk's five:

- **by thumb, no car reaches a gear it does not have, and none loses one**, for all seven cars;
- **and the knob rests only on a rail the car has, in a slot or on the cross rail.** A rail or slot that does not exist reads as neutral, so the gears check cannot see it. This check asks where the knob is.

**What was removed, and which harness owns it now.**

- The four-speed rail check, the slot below fifth, and the six-speed pull into sixth are in `gate-rails-test.py`, by thumb, with falsifiers (EVD-813). The new rests-only check also covers them for all seven cars.
- The black-knob car list is in `knob-test.py`, which reads `BODY_CLASS` as its oracle in both games (EVD-814). gate-test keeps only the white-text check. It reads the working set from the engine (every body that sets `body.workknob`) and fails if that set is empty.

The gearbox-band, box-coverage and plate-size checks are unchanged. No other harness covers them.

**Two harness faults were found and fixed during the work.**

1. On a five-speed's third rail, a pull down leaves the knob on the cross rail. The first scan's "middle row" was therefore in the bottom zone, and the next car's walk found no rail. The scan now runs a second time on the first rail, which has a bottom slot on every car.
2. With five browsers running at once, the run ended part-way through the walks. The veil then covered the plate, and every press landed on the veil (the diagnostic named `veilBody`). The harness now calls `setTimed(false)` and `holdSpd(0)`; neither changes the gate. The walk also waits until no animation moves the knob, requires the listener's own `grab` class before it reads anything, and names what is under the pointer if the drag never arms.

The plate wait is now `until` on a real box width, not a fixed 1000 ms sleep (RLG-220).

**Proof (EVD-812).** A clean run and five `--falsify` runs, all six at once for load. Each falsifier must turn its named check to `FAIL`, and the clean run must pass all three repaired checks:

| Falsifier | Defect served back | Check that failed |
|---|---|---|
| `rails` | drag loop over `RAIL_X.length` (RLG-220) | rests only on a rail the car has: four-speeds on rail 2 |
| `slots` | `gateSlots` unfiltered | gears: the five-speeds reach 6 |
| `lose` | drag loop one rail short | gears: every car loses its top rail |
| `below` | drag path without its slot check (RLG-236) | rests only in a slot: the five-speeds rest at rail 2, y 62 |
| `white` | `body.workknob #knob b` rule deleted | the working knob's text is white |

EVD-811 is a failed first attempt at that step: `step.py` could not start the interpreter without its `.exe` suffix (exit 127). Smoke passes (EVD-815).

**What the proof cannot check.** It requires each named check to fail. It does not require every other check to stay ok under that falsifier. The proof script ran from the session scratchpad and is not committed; its output is in EVD-812. The walk reads the engine's report of the knob, not the pixels. Whether the knob looks right on the plate is the owner's verdict on the device, and `gate-rails-test.py` checks the knob drawn over the stub rail.

**FOR THE OWNER: the gearbox `API.shift(dx, dy)` in `road.js` (next to `API.gate`) is dead.** The police shift's `API.shift()` overwrites it. No player sees this: it is harness surface, and no harness calls the gearbox version now. It was not changed here, because this unit repairs the harness and not the game. Removing the dead wrapper, or renaming it, is a one-line decision for a later unit.
