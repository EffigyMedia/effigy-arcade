### RLG-148 — The bridge rises at the end instead of falling: check both mouths of both events
- **RULED 2026-09-01T17:04:53-04:00** — Owner, 2026-09-01, mid-session: "it seems like the bridge goes up at the end and not back
down. I wasn't fully paying attention so I wonder if when the bridge starts if it goes down or
it goes up. We might need to check the bridge entrance and exit as well as the tunnel entrance
and exit that they follow the right shape."

THE OWNER IS NOT SURE WHAT THEY SAW AND SAYS SO, WHICH IS THE INSTRUCTION. The ask is not
"invert the bridge" - it is to MEASURE both mouths of both events and report what shape they
have. [[RLG-041]] cost eleven versions to a defect that was diagnosed from a guess, and this is
the same kind of report: a shape noticed in passing, at speed, with no capture.

THE SHAPE IS AUTHORED AND THE FORMULA LOOKS RIGHT ON PAPER. `profileSlope` returns a slope
that `authoredSlope` hands to the integration, where it REPLACES `dy`. Read at a few values it
gives `+rise` through the first sixth, zero across the middle, and `-rise` through the last
sixth: up, flat, down for a BRIDGE at `rise: 0.50`, and down, flat, up for a TUNNEL at
`rise: -0.34`. So the arithmetic is symmetric, and if the road is not, the fault is in what is
fed to it rather than in the shape itself.

WHICH MAKES THE EXTENT THE FIRST THING TO MEASURE, NOT THE FORMULA. `authoredSlope` answers
null outside `t` in 0 to 1, and `t` is `(z - eventZ0) / eventLen`. Three ways that ends the
event before the descent has been driven, and each is checkable:

    THE PLACE ENDS BEFORE THE PROFILE DOES. `eventLen` comes from `placeSpan`, and the biome
    crossing has its own band. If the road leaves BRIDGE while `t` is still below the last
    ramp, the descent is never driven and the deck simply stops being authored at whatever
    height it had reached - which is exactly "up at the end and not back down".

    THE PROFILE IS RE-ARMED PART WAY THROUGH. `eventZ0` is written when a place is placed at
    the horizon. If it is written twice, `t` restarts and the road climbs the first ramp again.

    THE SLOPE IS REPLACED BUT THE HEIGHT IS NOT RETURNED. The integration replaces `dy` inside
    the event, so leaving it hands the terrain back whatever height accumulated. Up and down
    should cancel exactly; a truncated event leaves a permanent step.

HOW TO MEASURE IT. `API.riseProfile(key, n)` integrates the profile the same way the road does
and returns the height at each of n points, so the AUTHORED shape can be printed without
driving. `API.roadSlopes` reads what the road actually has. The check is that those two agree
across a whole event, at both ends - the authored answer is only the intention, and the whole
report is that the road may not be following it. `tools/bridge-test.py` and
`tools/event-test.py` are where this belongs.

AND THE TUNNEL IS THE SAME QUESTION WITH THE SIGN FLIPPED, which is why the owner named both.
A bore drops and comes back up; if the extent is what is wrong, the tunnel exits low and the
world is a step higher than it should be for the rest of the run.

A CAPTURE AT EACH MOUTH IS PART OF THE ANSWER. `tools/biome-shot.py --approach FARMLAND,BRIDGE`
already photographs an approach, and the exit needs the same treatment.
