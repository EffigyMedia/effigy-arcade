### RLG-255 — The debug switches UNLOCK ALL RACERS and UNLOCK POLICE open no car
- **RULED 2026-09-15T03:07:54-04:00** — OWNER, 2026-09-15, while asking for a test with speed traps switched off: "the debug toggles we have in our debug menu no longer work".

FOUND. OPTIONS > DEBUG flips `dbgRacers` and `dbgPolice`, and no code read either variable. `carLocked` decided ownership alone, so a locked car stayed locked with both switches ON. RLG-249 had already recorded that `carLocked` never read the switches. The switches last had an effect through `openBy` in `garageBodies`, and the silhouette garage (owner, 2026-09-08) moved the lock decision to `carLocked` without them.

BUILT IN 0.14.29. `carLocked` returns false when the matching switch is on: `dbgPolice` for a body with `force`, `dbgRacers` for every other body. `unlocked()` is unchanged, so the save still records the car as locked and the reward screens can still be earned. The switches are still not saved; a reload turns them off.

PROOF. tools/debug-unlock-test.py taps OPTIONS, DEBUG and each switch in both driving cabinets on a fresh save. It asserts that every racer opens, that the police cars stay locked until UNLOCK POLICE, that the garage offers DRIVE on a car only the switch opened, that the save's flags do not change, and that a reload turns the switches off. It passes on 0.14.29 and fails six checks against the old `carLocked`. locked-garage, garage-order, class, novelty and smoke pass.
- **RULED 2026-09-19T16:03:07-04:00** — RECHECKED 2026-09-19 on the owner's request to build this again: it is already built (0.14.29) and still holds after the garage was split into three screens (0.14.90). tools/debug-unlock-test.py passes every check in both driving cabinets on 0.14.94 - every racer opens on UNLOCK ALL RACERS, police cars stay locked until UNLOCK POLICE, the save's flags do not change, a switch-opened car offers DRIVE, a reload turns both off.
