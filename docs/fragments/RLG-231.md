### RLG-231 — The deployed build is read from the remote, never from the thread

**MEASURED 2026-09-12**, at the moment of pushing, by a command that should have been run six hours
earlier.

---

## WHAT WAS CLAIMED, AND WHAT IS TRUE

Throughout this session the deployed build was stated as **v0.13.89**, with *"fourteen builds
unpushed"* and later *"sixteen"*. It went into three fragments and was said to the owner twice.

    $ git show origin/main:arcade.js | grep -m1 A.version
    A.version = '0.14.1';

**Five commits were unpushed, not sixteen.** The deployed build was v0.14.1.

## WHY IT MATTERS, WHICH IS MORE THAN THE NUMBER

[[RLG-213]] landed across v0.13.88 to v0.13.93. At v0.13.89 the owner's phone would have had almost
none of it; at **v0.14.1 it had all of it**. So when the owner said the circuit holds only sports,
super and formula *"like before"*, the explanation offered to them - *your device has not seen the
change* - **was impossible**, and a whole paragraph of [[RLG-226]] was written on it.

The owner corrected it themselves, plainly, and it took a second exchange: *"the little car classes
do not translate between the two games."* **It was a ruling, and it was read as a stale build.** An
owner should not have to spend a message undoing an explanation that one command would have
disproved.

## WHERE THE NUMBER CAME FROM

**The thread fragment**, which had said v0.13.89 when it was written and had gone stale since. That
is not a fault in the thread: a thread records what was true at the checkpoint. The fault is that a
number *about the outside world* was read out of a record and then repeated as measurement, twice to
the owner and three times into the store, without being checked once.

**This is the shape [[RLG-066]] already names** - *"NOTHING IN THE HARNESS SUITE KNOWS WHAT IS
DEPLOYED"* - and it predicted the cost precisely: *"a check that compares the committed version with
the one the Pages site is serving would have caught the 46-commit gap on its first run."* It would
have caught this too, in the other direction: the gap was smaller than claimed, and being wrong
about it the safe way is still being wrong.

## THE RULE

**Before any statement about what the owner is running, read the remote.**

    git fetch origin && git show origin/main:arcade.js | grep -m1 A.version
    git log --oneline origin/main..main | wc -l

One command each. The thread, the changelog and the fragments record what was true when they were
written; **the remote is the only thing that knows what is deployed now.** A number that describes
something outside this repository is measured at the moment it is used, or it is not stated.

## WHAT WAS DONE

[[RLG-226]]'s wrong paragraph is **kept and marked** rather than edited away, so the mistake stays
visible next to the correction. [[RLG-227]] and [[RLG-229]] carry a line each saying the owner's
words on the circuit were a ruling rather than a device report.

**Still not built:** the deploy-gap check [[RLG-066]] asked for. It has now been the missing
instrument twice, in opposite directions.
