### RLG-078 — Muting a bus does not mute its reverb: the reverb return goes straight to master
- **RULED 2026-08-29T16:03:16-04:00** — Owner, 2026-08-29, filed to be recorded and NOT started: "This is an issue with the whole arcade, but
if I was to mute the music, the reverb bus still plays so we want to make sure muting the music also
mutes that bus."

THE CAUSE IS IN THE ROUTING AND IT IS PLAIN. `audio.js` builds four gain nodes at start-up. Three of
them are buses that the mute drives - `sfxBus`, `musBus`, `uiBus` - and each connects to `master`.
The reverb is the fourth path and it does NOT go through any of them:

    verb = buildVerb();
    var vg = ctx.createGain(); vg.gain.value = 0.85;
    verb.connect(vg); vg.connect(master);          <- audio.js:206, straight to master

A voice that wants reverb is connected twice. The dry copy goes to its bus; the wet copy goes
`g -> vs -> verb`, and out of the verb network to `master`. So `applyGains()` setting `musBus.gain`
to zero silences the dry music and leaves its tail ringing, which is what the owner heard.

IT IS WIDER THAN THE REPORT. The same is true of the sound-effects bus: muting SFX leaves the reverb
of every effect audible, and `quiet()` - the whole-arcade mute - has the same hole. The owner only
noticed it on music because a music bed feeds the reverb continuously and an effect does not.

WHAT THE FIX PROBABLY IS, and it is not the obvious one. Muting the single reverb return would fix
the report and break the sound effects: one return carries both, so killing it when MUSIC is muted
takes the effects' reverb with it. The clean shape is a send and return PER BUS - the music voices
feeding a reverb that returns into `musBus`, the effects feeding one that returns into `sfxBus` - so
each tail rides the gain that already mutes its own dry signal, and nothing new has to know about
muting at all.

THAT COSTS A SECOND CONVOLVER, which is the trade to weigh when this is picked up. A cheaper option
is one convolver with two return gains, each mirroring a bus, and each voice sending to the return
that matches where its dry copy went.

HOW TO PROVE IT, because a check that reads a gain value off the Web Audio graph is not reading the
graph - RLG-065 cost three attempts on exactly that, and a GainNode on a closed context reports a
healthy value quite happily. What works here is asking the graph WHERE the reverb return is
connected, and asserting that muting a bus leaves nothing audible downstream of that bus. The
existing `tools/audio-test.py` already reads the graph rather than listening, so it is the right
home.

NOT STARTED. Recorded at the owner's request: "It's not a big deal right now. I just want to record
it."
- **RULED 2026-08-30T10:19:52-04:00** — A REVERB PER BUS, RETURNING INTO THE BUS. Built as the fragment described, and the fragment's own
"cheaper option" turned out not to exist: one convolver with two return gains cannot work, because a
convolver mixes everything sent to it into ONE output and there is nothing left to separate the
music's tail from the effects'. A tail can only ride the gain its dry copy rides if it comes out of a
convolver that only that bus feeds. So it is a convolver per bus, built the first time a voice sends
to that bus - in play, two get built.

THE MEASUREMENT IS THE PART THAT TOOK THE WORK, and it failed twice before it meant anything.

FIRST, THE ROOM WAS NOT EMPTY. The title screen plays a music bed, so the analyser was reading the
game rather than the harness: the floor measured 0.21 with music on and 0.00 with music muted. That
difference is exactly the shape of the thing being tested, and a check that read it would have
"proved" the fix on a build that still had the fault. The bed is paused before anything is measured,
and the floor is asserted to be silent - 0 to 2e-06 against a signal of 2.9e-03.

SECOND, A 1.9-SECOND TAIL OUTLASTS THE PHASE THAT MADE IT. Measuring one condition 520ms after the
last carried the previous tail into it, and un-muting a bus brings back whatever is still ringing
inside its convolver - so a muted bus read 0.0009 where it should have read zero, and an unmuted one
read high for the wrong reason. Every measurement now waits for silence first and checks that it got
it.

THIRD, ONE READ OF A DECAYING TAIL IS A LOTTERY. A 2048-sample window landed at 0.00024 and 0.00066
on the same condition, purely on where it fell. Five reads across the tail, loudest wins.

AND THE FALSIFICATION IS THE OWNER'S REPORT AS A NUMBER. Put the return back on master and muting the
music leaves its tail at 0.00261 against 0.00295 unmuted - 88 per cent of full, which is what "the
reverb bus still plays" sounds like. Both directions fail, because the check asserts both: a fix that
muted the single shared return would have silenced the report and taken the effects' reverb with it,
and this check would have caught that too.

ONE THING NOT PROVEN HERE, AND IT IS RLG-039 RATHER THAN THIS. `tools/audio-test.py` passes when run
directly - all fourteen checks - but fails under `step.py` with a 404 on the cabinet it loads,
because it serves the folder from a relative path and step.py runs it from somewhere else. EVD-063
records that failure faithfully rather than hiding it. It is the next unit.
