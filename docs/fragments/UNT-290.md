### UNT-290 - The non-racing class is UTILITY, and no save loses a car

- Routing class: `change` -> **claude-opus-5**, effort **high**. Bias 1. A policy or vocabulary change reaches every file that follows it. ([[RLG-092]])
- Opened for: [[RLG-227]]
- Opened by `unit.py`. **The identity exists before the first edit** ([[RLG-097]]), so the snapshot has somewhere to go.
- **CLOSED 2026-09-12T22:16:44-04:00** - v0.14.5. The owner asked for one name covering the cab, the pickup, the van, the lorry and the ambulance, and chose UTILITY. The class was called traffic, which was picked because it was already the flag in the save and so needed no migration - but traffic is something a vehicle DOES on the road rather than a kind of vehicle, and the production cars fill it too, so the name was true of cars outside the class. The identifiers moved with it: TRAFFIC_MILES to UTILITY_MILES, wonTraffic to wonUtility, dbgTraffic and API.dbgTraffic to dbgUtility, and the debug button reads UNLOCK ALL UTILITY. Leaving those spelled traffic would have been the first step of the drift this fixes. THE PLAYER-FACING LABEL NEEDED NO EDIT AND THAT IS THE POINT - the garage note is bodyClass(optBody).toUpperCase() plus TEST DRIVE ONLY, so it read TRAFFIC before and reads UTILITY now because the class changed underneath it; class-test reports the new string. THE MIGRATION COST ONE ENTRY. OLD_UNLOCK_NAMES already existed for the resort, so it went from { traffic: [production, utility] } to { utility: [traffic, production] } - and because the new name is one of the two PRE-resort flags, a save from that era is answered by the first line of unlocked without reaching the table at all. resort-test boots a save holding each of the three names in turn and asserts the whole class is offered; it gained a row for the new name and keeps the rows for the old ones, because a migration is never removed and neither is its test. The owner also confirmed that production keeps the working wheel and knob, which settles what RLG-226 had to leave open: the wheel and the knob answer what KIND of vehicle this is, not which class it is in, because they cover production and utility both. knob-test now says so in its own words instead of leaving the pair of class names looking like an oversight. class-test, reach-test, knob-test, fleet-sheet and resort-test followed the rename, and docs/fleet/traffic.png is docs/fleet/utility.png.
