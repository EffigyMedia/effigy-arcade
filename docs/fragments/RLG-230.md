### RLG-230 — One unlock rule: utility at a hundred miles, and no other

**RULED 2026-09-12.** Owner, shown the table of three flag names that all opened the class: *"So
nothing should unlock at 50 and 25 miles, traffic unlocking at 100 is incorrect and utility unlocking
at 100 is the only correct, because now all those vehicles only fall under utility."*

---

## WHAT WAS THERE

The non-racing class has been earned three different ways as the fleet was reorganised:

| When | Flag written | Paid at |
|---|---|---|
| before 2026-08-29 | `production` | 50 miles |
| before 2026-08-29 | `utility` | 25 miles |
| the resort ([[RLG-213]]) | `traffic` | 100 miles |
| [[RLG-229]] | `utility` | 100 miles |

`OLD_UNLOCK_NAMES` read all of them as the current one, so that no save lost a car. That was the
right instinct and it is the wrong rule.

## WHY IT IS WRONG, IN THE OWNER'S REASON

**The old names describe a fleet that no longer exists.** There is one non-racing class, so a flag
saying *"this player won the utility half at 25 miles"* is a claim about a split the game does not
have - and honouring it hands somebody five vehicles for a quarter of the distance the rule asks
for.

**A migration is supposed to carry a save across a RENAME. This one was carrying it across a CHANGE
OF RULE**, which is a different thing wearing the same coat. `traffic` to `utility` is a rename and
the distance did not move; `production` at 50 and `utility` at 25 are a different bargain, and
reading them as the new flag imports the old bargain with them.

## WHAT CHANGED

`OLD_UNLOCK_NAMES` is removed and `unlocked()` reads one key:

    function unlocked(key){
      const sv = (AR && AR.save) ? AR.save.get((GAME_ID + '-opts')) : null;
      return !!(sv && sv[key]);
    }

## WHAT IT COSTS, STATED BEFORE IT WAS BUILT

**A save holding only the old `traffic` flag drives the hundred miles again.** The owner was told
that, and that it would apply to their own device on the build being pushed, and ruled anyway.

**AND ONE THING CANNOT BE UNDONE.** The pre-resort 25-mile flag was spelled `utility`, which is the
name the class carries now, so an old save and a new one are **the same key** and no code can tell
them apart. *"Nothing unlocks at 25 miles"* holds for every save written from here on and cannot be
enforced backwards for that one spelling. That is recorded in the engine's own note rather than
papered over with a check that would have to lie about it.

## THIS IS NOT A REPEAL OF RLG-197

[[RLG-197]] is about the **body keys** in `RENAMED` - `FORMULA` to `APEX`, `LORRY` to `SEMI` - where
a rename would otherwise silently swap somebody's car for a ROADSTER. **That table is untouched and
still never removed**, and `rename-test.py` still proves both. This was a second table that had
adopted the same principle, and the owner has ruled that the principle does not reach a change of
rule.

## THE PROOF

`resort-test.py` had a row per old name asserting each one opened the class. **The rows are kept and
turned over** rather than deleted - deleting them would leave the new rule with no check at all, and
the rule is the whole ruling:

    ok  the utility flag opens the whole class
    ok  the old hundred-mile flag opens NOTHING now
    ok  the old fifty-mile flag opens NOTHING now

The 25-mile flag has no row, and the test says why in its own comment: it cannot have one that would
not be a lie.
