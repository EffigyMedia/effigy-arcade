### RLG-275 — Two API.grid definitions, and the later one won
- **RULED 2026-09-16T04:00:09-04:00** — FOUND AND FIXED 2026-09-16, while building [[RLG-274]]. THERE WERE TWO `API.grid` DEFINITIONS IN `road.js`, about 800 lines apart, answering completely different questions:

- the STARTING LINE-UP, a row per rival with its speed, its base pace and its launch quality, written for `launch-test`;
- a CLASS QUESTION about the selected car - `{cls, entry, field}` - written for `resort-test`.

THE LATER ASSIGNMENT SIMPLY OVERWROTE THE EARLIER. No error, no warning: the last writer wins and the object is never sealed. So the line-up version had not existed for as long as both have been in the file, and every harness asking for it got an object with three keys.

`launch-test` HAS BEEN RED ON IT THE WHOLE TIME AND SAID SO CLEARLY: "a race grid is eleven rivals: it was 3" - three being the number of KEYS on the other object, counted by a check expecting a list of cars. The line after it then raised a TypeError reading `r['spd']` off a string, so THE WHOLE ROLLING-START SECTION OF THAT HARNESS HAS BEEN UNREACHABLE. It was not a silent failure; it was a loud one nobody followed.

THE FIX IS A RENAME AND NOT A MERGE. The line-up keeps `grid`, because that is what the word means on a race track and two harnesses ask it that way; the class question became `API.gridEntry`, which is what it actually answers. `resort-test`'s three call sites moved with it.

WHAT IT COST BESIDES THE DEAD CHECKS: nothing in the product. Both are debug seams and no game code reads either.

THE LESSON IS ABOUT THE SHAPE OF THE FILE. `road.js` attaches its API surface across hundreds of scattered lines, so two people - or one person twice - can name the same member without anything colliding at parse time. Nothing checks for it today. A scan for duplicate `API.<name> =` assignments is cheap and would have caught this the day it landed; that is not built, and it is worth building before the next seam is added.

AND IT IS THE REASON A THIRD THING WAS FOUND: with the line-up reachable again, `launch-test` now runs checks that have never run, and one of them fails. That is [[RLG-276]], and it is NOT caused by this rename.
- **RULED 2026-09-18T12:04:09-04:00** — FINISHED, v0.14.78 - the scan this ruling asked for is built, and it found the same defect again.

`tools/api-dup-check.js` strips comments, then lists every `API.<name> =` in `road.js` and fails on any name assigned twice. `pack.sh` runs it straight after the parse gate, so no build can ship with one. It found four:
    `shift` - the `grid` defect a second time. RLG-203's `API.shift()` (the police shift) replaced the gearbox's `API.shift(dx, dy)`. gate-test had already hit this and moved to a real pointer on the knob (RLG-244), so the gearbox version had no caller. It is removed, and a note stands where it was.
    `hasNos`, `seaSide`, `sideRoll` - identical second copies. Removed.

THE TWO-STAGE HELPERS ARE ALLOWED BY NAME. `rnd`, `rint`, `rr` and `segAt` are attached at the top of `ROAD()` as wrappers, because `onReset` fires before the function returns, and are replaced by the real functions later. That is the seam contract CLAUDE.md records. The check allows exactly two assignments of those names, the first above the file's "use strict" line; a third, or a first anywhere else, fails.

PROVEN: the check passes on this build, names exactly the four duplicates in the build before it and nothing else, and names a planted third `segAt`. `pack.sh --check` refuses the earlier `road.js` with "an API member is assigned twice". gate-test, shift-stop-test and smoke-test pass.

A TOOLING NOTE: EVD-1021 records `pack.sh --check` failing under `step.py`. That is `step.py` running bash on this machine: node cannot open its stdout (EISDIR). The same command passes when run directly, and the check is recorded by calling node directly in EVD-1025 and EVD-1026.
