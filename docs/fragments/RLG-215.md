### RLG-215 — The distance unlocks cannot be reached - a timed run ends between 1.4 and 9.2 miles
- **RULED 2026-09-12T04:40:07-04:00** — **THE OWNER ASKED WHETHER THE NEW MERGED UNLOCK SHOULD BE 50 MILES OR 100, AND THE ANSWER IS THAT
NEITHER IS REACHABLE - NOR IS THE 50 THAT IS IN THE CODE TODAY.** Measured 2026-09-12 by
`tools/reach-test.py`, nine runs across three cars, flat out, timer on.

    SALOON     3.81   1.39   3.22 miles      -> 1.39 to 3.81
    TUNER      2.61   3.07   5.53 miles      -> 2.61 to 5.53
    MUSCLE     5.38   9.01   9.23 miles      -> 5.38 to 9.23

Every one of the nine ended the same way: the clock reached zero and the run was over. The longest
was 9.23 miles.

## THE ARITHMETIC, WHICH IS WHY NO CAR CAN FIX THIS

    CLOCK_START   60s      a run begins with a minute
    CP_MILES      2        a checkpoint every two miles
    CLOCK_BONUS   20s      and it pays twenty seconds
    CRATE_SECS    10s      a crate pays ten, and crates are scattered

Twenty seconds for two miles is **360mph to break even**. The fastest car in the fleet declares
194. So the clock drains on every mile of every run in the game, and the only question is how fast:
about 8.6 seconds a mile at the top of the fleet and 12.5 in a MUSCLE. Sixty seconds of margin
divided by that is the whole run. **A crate is the only thing that pushes back**, which is why the
spread is so wide - the four-crate MUSCLE run went half as far again as the two-crate one.

## SO BOTH UNLOCKS IN THE CODE ARE DEAD, AND THEY ARE CITED AS LIVE

    if(mode !== 'race' && timedRun){
      if(dist >= 25 && !unlocked('utility'))    ...
      if(dist >= 50 && !unlocked('production')) ...
    }

`dist` is reset to zero by `reset()` on every run, so both are asked of ONE run with the timer on -
and one run ends at nine miles at the very best. **The utility class at 25 miles and the production
class at 50 miles cannot be won by driving.** `UNLOCK_HOW` does not list either, because they are
the two SECRET unlocks, so the game never states a condition that a player could discover was
impossible.

**A CAR IN THOSE CLASSES THEREFORE CAME FROM SOMEWHERE ELSE**: the older hundred-mile `traffic`
flag, which `carLocked` and `openBy` both still honour as a fall-through, or the DEBUG switch -
which has its own defect, [[RLG-214]], and does not actually let the car be driven either.

## WHAT MADE THIS INVISIBLE

The trigger is guarded on `timedRun`, and the timer is the thing that ends a run. So the only mode
in which the distance can be earned is the only mode in which distance is capped. **Nothing in the
harness suite had ever driven a run to its end** - `verify-097-100.py` drives for a fixed 95 seconds
and asks whether the clock survived, which is a different question and it answers it correctly.

## THE THREE WAYS OUT, AND THEY ARE THE OWNER'S TO PICK

    1. DROP THE TIMER REQUIREMENT. Count distance on any test drive. Fifty miles then
       becomes about twenty minutes of driving and the number in the code needs no
       change. It also makes the unlock a test of patience rather than of driving.
    2. MAKE THE ODOMETER CAREER-LONG. `dist` stays per-run for the HUD and a second
       total accumulates into the save. Fifty or a hundred miles then means what the
       owner thinks it means. It is a new persisted value, so it is a migration.
    3. KEEP IT PER-RUN AND TIMED, and set the number to something a run reaches -
       which today is about five miles, with a ceiling near nine.

**AND THERE IS A FOURTH THAT IS NOT ON THE LIST.** Raising `CLOCK_BONUS` or shortening `CP_MILES`
would make long runs possible, and it would change every run in the game rather than the unlock.
That is a tuning decision about the whole mode and it must not be made as a side effect of an
unlock condition.
- **RULED 2026-09-12T08:46:19-04:00** — **WITHDRAWN. THE FINDING IS WRONG AND THE OWNER'S REPORT IS RIGHT.** Owner, 2026-09-12: *"I've
driven over 100mi no problem multiple times. The average run is either dozens of miles or N/A
because I quit before losing."* The measurement above did not measure the game. It measured a

## THE TWO VARIABLES I LEFT OUT, AND BOTH BELONG TO THE DRIVER

**CRATES ARE PARKED ON THE SHOULDER.** `crates.push({ z: ..., x: side * rnd(0.86, 1.02) })`, and
the line above it says so in the source: *"parked on the shoulder, so taking one means leaving the
road."* The harness drove straight down the middle for every run, so it collected a crate only when
one happened to fall across its path - zero to four in a whole run. **A player steers to them.**

**AND IT NEVER REACHED THE SPEED THE CARS HAVE.** Peak speeds were 98 to 156 mph in a fleet whose
top car declares 194. Headless, at a frame rate this machine chose.

Both of those are the driver, and this project has the lesson written down already: **do not
believe a number the driver can influence.** It was written after a harness reported that Raceway's
tyres died in twenty seconds, when the autopilot sawing at the wheel was the cause. This is the
same error with the wheel held still instead.

## THE ARITHMETIC, DONE PROPERLY THIS TIME

The clock loses one second a second. Two things pay into it, and **the crate pays on a TIMER rather
than by distance** - `nextCrateT = rnd(20, 34)` - which is the term the first version omitted:

    checkpoints   20s every 2 miles   ->   v / 360 seconds a second, at v mph
    crates        10s every 20-34s    ->   0.29 to 0.50 seconds a second, IF taken
    the clock                         ->   -1 second a second

    net = v/360 + crate - 1

    194mph, every crate taken, at the fast end    +0.04   THE CLOCK CLIMBS - endless
    194mph, every crate taken, at the mean        -0.09   about 11 minutes, ~35 miles
    150mph, every crate taken, at the mean        -0.21   about 4.7 minutes, ~12 miles
    150mph, crates missed                         -0.58   about 1.7 minutes, ~4 miles

**THE LAST ROW IS WHAT THE HARNESS MEASURED**, and the first row is what the owner plays. The mode
is sustainable at the top of the fleet when you keep taking crates, and it falls apart quickly when
you do not - which is a design that works rather than one that is broken.

## SO WHAT THE NINE RUNS ACTUALLY ESTABLISHED

A FLOOR, and only a floor: **1.39 to 9.23 miles is how far a run goes when nobody steers.** That is
a real number about a real code path and it is not the ceiling, and every sentence above that read
it as a ceiling was wrong. The unlocks at 25 and 50 miles are NOT dead, `UNLOCK_HOW` is not hiding
an impossible condition, and nothing here needs fixing.

**THE THREE WAYS OUT ARE WITHDRAWN WITH IT.** There is nothing to escape from.

## WHAT THE ERROR COST AND WHAT STOPS IT NEXT TIME

The falsifier that was built into the harness did its job and could not have caught this. It proved
the odometer and the run-end detection scale past the measured ceiling - which was true, and which
says nothing about whether the DRIVER was representative. **A falsifier answers "can this harness
report the other answer". It does not answer "is the thing being driven the thing the player
drives".** The second question needs a driver check: this harness should have refused to report at
all while its peak speed sat a third below the car's own declared top end, and while its crate
count sat at zero.

[[RLG-214]] is UNAFFECTED. The debug switches really do list a car they will not let you drive, and
that was proved by changing one variable.
