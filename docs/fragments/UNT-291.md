### UNT-291 - One unlock rule: utility at a hundred miles, and no other

- Routing class: `change` -> **claude-opus-5**, effort **high**. Bias 1. A policy or vocabulary change reaches every file that follows it. ([[RLG-092]])
- Opened for: [[RLG-229]]
- Opened by `unit.py`. **The identity exists before the first edit** ([[RLG-097]]), so the snapshot has somewhere to go.
- **CLOSED 2026-09-12T23:06:48-04:00** - v0.14.6. The non-racing class had been earned three ways as the fleet was reorganised - production at 50 miles and utility at 25 before the resort, traffic at 100 after it, utility at 100 now - and OLD_UNLOCK_NAMES read every old spelling as the current one so that no save lost a car. The owner ruled that only the last is correct. THE REASON IS THAT THE OLD NAMES DESCRIBE A FLEET THAT NO LONGER EXISTS: there is one non-racing class, so a flag saying the player won the utility half at 25 miles is a claim about a split the game does not have, and honouring it hands over five vehicles for a quarter of the distance. A migration carries a save across a RENAME; this one was carrying it across a CHANGE OF RULE, which is a different thing wearing the same coat. OLD_UNLOCK_NAMES is removed and unlocked() reads one key. THE COST WAS STATED BEFORE IT WAS BUILT: a save holding only the old traffic flag drives the hundred miles again, including the owner's own device on the build being pushed, and they ruled anyway. AND ONE THING CANNOT BE UNDONE - the pre-resort 25-mile flag was spelled utility, which is the name the class carries now, so an old save and a new one are the same key and nothing can tell them apart; that is recorded in the engine's note rather than papered over with a check that would have to lie. THIS IS NOT A REPEAL OF RLG-197: that ruling is about the BODY keys in RENAMED, where a rename would silently swap somebody's car for a ROADSTER, and that table is untouched and rename-test still proves it. resort-test's rows were KEPT AND TURNED OVER rather than deleted - each old flag is now asserted to open NOTHING - because deleting them would leave the new rule with no check at all.
