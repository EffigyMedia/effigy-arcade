### RLG-050 — A debug jump to a tournament finish, so reward changes can be tested
- **RULED 2026-08-28T17:48:19-04:00** — **Found while shipping [[RLG-049]], which is the point.** That unit changed what a tournament gold
pays out, and no harness could execute the branch it added: a tournament is four races of 10, 12, 16
and 24 miles, and there is no way to reach a finish except by driving one. So a reward change ships
on a static parse, which this project's own rule says is not evidence.

**What is wanted:** a debug action that jumps to a tournament finish with a chosen standing, next to
the two that already exist in `showDebug` - UNLOCK ALL RACERS and UNLOCK ALL TRAFFIC. Enough to set
`tourOn`, `tourRound` and `tourPts` such that the final-round branch runs and `showTrophy` is
reached.

**It must not write an unlock flag by itself.** The debug panel's existing two switches are careful
about this - road.js:9549 records that they 'open a car in the garage WITHOUT writing the unlock
flag', and `unlocked()` is untouched by them. A jump that granted the prize directly would test
nothing: the whole point is to run the real payout branch and see what it writes.

**The alternative was considered and rejected.** Exposing `showTrophy` on the `API` seam would let a
harness render the screen, but that seam is documented as 'deliberately small - anything wider and a
fork starts depending on the engine's internals rather than on its interface', and a UI function is
not part of a fork's interface. A debug action is the right home: it is already the place where
'things a developer needs and a player must not have' live.

**Once it exists, the first thing to do with it is verify RLG-049**, which is currently accepted on
the owner's word rather than on a test.
