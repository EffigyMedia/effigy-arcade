### RLG-272 — Leaving a run cuts the run's sounds
- **RULED 2026-09-16T02:21:36-04:00** — TRACKED, NOT STARTED. Owner, 2026-09-16: "When you get to the game over screen essentially they're still looping engine sounds that make it sound ugly. We need to cut the run sounds when we leave a run."

THE RUN'S HELD SOUND LAYERS OUTLIVE THE RUN. The engine note, and anything else the run holds open, keeps sounding under the end card. `menuMusic()` is called when a run ends, so the MUSIC changes over, and the held voices are what is left running underneath it.

IT IS ONE RULE AND NOT ONE SCREEN. Every way out of a run has to silence the run - the end card, the trophy, the unlock card, the garage reached by CHANGE CAR, the title reached by MAIN MENU, and a pause that is never resumed. A fix applied at `showEnd` alone leaves the other doors sounding, and the doors are now enumerated in [[RLG-251]].

`snd.quiet()` already exists and is called on one of those paths. Find what it silences and what it does not, because the complaint says something survives it.

AND IT MUST NOT COST THE MENU ITS OWN AUDIO. The menu music is meant to be playing under the end card; only the run's voices go.
- **RULED 2026-09-16T02:32:59-04:00** — BUILT, v0.14.48. THE ENGINE WAS THE ONE VOICE `snd.quiet()` DID NOT TURN OFF. Every other held layer in it goes to a gain of zero; the engine went to 0.01 and stayed there. Measured through `API.snd` on the live Web Audio graph: eng 0.0899 while driving, 0.0100 on the end card with everything around it at zero, and 0.0100 still in the garage. A held oscillator sounds until something tells it to stop, so that was a 60 Hz sawtooth droning under every menu for as long as the tab was open. The 0.01 was inherited whole at the fork and was never chosen - `git log -L` on the line finds only the fork commit.

THE FIX IS THE VALUE THE EXISTING RAMP AIMS AT, and nothing else. `snd.eng.set(60, 0, 300, 0.4)` keeps the 0.4-second ramp that was already there, so the engine fades OUT rather than fading down to a hum and staying there. The two horn voices were added to the same function: they are held layers on the same list and were the only others it did not name.

AND IT IS THE RIGHT PLACE FOR IT, because every caller of `quiet()` is a run that is over - `dead()`, `endRun()`, the finish, `endShift()`, and the per-frame `coasting` branch, which is only true once the race is decided and the player is no longer driving. None of them wants an idle. A fix at `showEnd` alone would have left the other doors sounding.

`tools/run-silence-test.py` IS THE PROOF AND IT WAS WATCHED FAILING. It drives, ends the run on the clock, and reads every held layer off the graph on the end card, four seconds later, and again in the garage. `--selftest` writes the old 0.01 idle back onto the engine after the run has ended and the file reports it on two checks. THE CHECK IS A FLOOR AND NOT AN EQUALITY, for a stated reason: `set()` ramps with `setTargetAtTime`, which is exponential, so a layer told to go to zero approaches it and never arrives - it reads 0.00008 two seconds in and a true zero four seconds later. The floor is 0.0005, about 180 times below the driving engine and 20 times below the idle that is the defect, so it separates the two cases rather than splitting the difference. The file also asserts the audio context is RUNNING before believing any gain, because a GainNode on a closed context reports its value perfectly happily.

WHAT THE HARNESS CANNOT SAY. It walks OUT OF TIME and CHANGE CAR. The trophy card, the unlock card and a wreck are not walked, and neither is INTERCEPT. All of them reach the same `quiet()`, which is why the fix was made there rather than per screen, but that is reasoning rather than measurement. AND IT CANNOT LISTEN: a gain of zero on a live context is silence by construction, not by ear, so the owner's verdict on the device is still what closes this.
